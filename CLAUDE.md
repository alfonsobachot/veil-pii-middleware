## Project

PII sanitization middleware for Claude Code, built around a tokenization /
de-tokenization cycle. Raw personal data never leaves the machine: values are
replaced with stable `PII_<TYPE>_<NNNN>` tokens before any payload reaches an
external API, and the substitution is reversed for local tools so database
queries and file reads keep operating on the real values.

Users: developers who debug production incidents with Claude Code against
systems that hold customer PII.

Lifecycle stage: early skeleton. The package layout, lint/test configuration
and this harness exist; no detection, vault or adapter logic is implemented
yet. The design of record is `docs/private/BRIEF.md` (git-ignored).

## Stack

Python, `pyproject.toml` with the Hatchling build backend, `pip` + `venv` for
dependencies, `ruff` for lint and formatting, `pytest` for tests. No runtime
dependencies yet; SQLite (vault and demo database) and a local LLM served by
Ollama are planned.

Runtime versions: `requires-python = ">=3.11"`; the local `.venv` runs Python
3.12.10.

Layout:

```
veil_pii_middleware/
  core/       detector, vault, tokenizer, audit
  adapters/   command (/ask), hooks, gateway
  frontend/   live observability panel
  demo/       seed (database + manifest), eval (recall / precision)
tests/        pytest suite
```

## Project Conventions

**Architecture.** One shared `core/` (detector, vault, tokenizer, audit) applied
by three adapters at three interception points (command, hooks, gateway).
Adapters never re-implement detection or substitution; they only wire `core/`
into a transport.

**Detection.** Hybrid and always both layers, unioned. The regex layer is the
guaranteed floor and requires check-digit validation — DNI/NIE letter, IBAN
mod-97, card Luhn. The local LLM layer returns spans as JSON, never rewritten
text; substitution happens in code. On overlapping spans the longest wins; ties
go to regex.

**Tokens.** Format `PII_<TYPE>_<NNNN>`. The same normalized value must always
map to the same token within a session — otherwise the model cannot correlate
rows and gateway-mode prompt caching breaks.

**Security.** No raw PII may reach an external API, a log, or harness memory.
The vault stores AES-GCM ciphertext plus an HMAC-SHA256 lookup, never
plaintext; the master key comes from the environment or a keyring, never from
the repository. The audit log is append-only and never records plaintext.

**Fail-closed.** When detection cannot run, block rather than forward. The
`UserPromptSubmit` hook can only block (exit 2), never rewrite.

**Data.** The demo database is fully synthetic (Faker, fixed seed). The vault,
generated databases and audit logs are git-ignored and must never be committed.

**Testing.** `pytest` under `tests/`. Ruff enforces `E,F,I,UP,B,SIM` at line
length 100 with double quotes. `mypy` runs in `strict` mode over
`veil_pii_middleware` and `tests` — no untyped defs and no implicit `Any`,
because an unchecked `Any` around spans, bytes or ciphertext hides exactly the
class of bug that leaks PII. Detector changes are measured with
`demo/eval.py` (recall / precision) against the seeded ground-truth manifest,
not by eyeballing output.

**Review and risk.** Changes to detection, vault or tokenization are the
high-risk surface: a missed span is a data leak, and an unstable token silently
breaks correlation. They require human approval before merge.

**Vendored code.** `.harness/` holds upstream harness tooling. It is excluded
from ruff in `pyproject.toml` and is not project code — do not reformat it to
match house style.
